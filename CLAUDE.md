- Pull requests: after pushing, open the PR and merge it into `main` right away (squash), without asking the owner first. Run the local checks (`npm test`, `npm run build`, and the Python tests touched) before merging.
- Zak Onn's voice (league owner, 23.10.2026, a standing rule): every word of Zak Onn — protocols, statements (`data/announcements/`), his lines and picture scenes — is for the league, not for developers. He knows nothing about programming and everything about law, cases and shady types. Never cards, ids, registries, databases, bots, code, collections or counts of checked records: say it as a case — a suspect, documents, an investigation, a verdict. Short, punchy, a 90s law-and-order action film. Every statement goes with its own picture (the idea of a strong image of its point in `<file>.picture.txt`, never a plain portrait).
- Pictures (league owner, 23.10.2026, a standing rule): no prompt is prepared in code — no scenes, styles, templates or fallbacks. Claude writes every picture's prompt whole, thinking over the context (`scripts/picture-prompt.mjs` `writePicture`); the code only gives the references (the participants' faces, the logos) with who is on each, checks the prompt and sends it as written. When Claude cannot write one, there is no picture.
- FBL points (league owner, 22.10.2026, a standing rule): every FBL number — site, bots, audits, forecasts — goes through the league's official formula, `fblFormula` in `src/fbl-scoring.js` and `fbl_points` in `scripts/fbl_formula.py`: PTS+REB+AST+STL+BLK−(FGA−FGM)−(FTA−FTM)−2·TO−PF+1 per game played. The formula is the truth. Sources (Sports.ru's game table, ESPN's box score) only supply the box-score numbers; Sports.ru's own ФО or any provider's points are never FBL points and never a reason to doubt the formula. Every implementation must give the golden lines of `tests/fixtures/fbl-formula-golden.json`.
