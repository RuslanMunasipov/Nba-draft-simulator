# Реестр источников FBL — этап 1

Это договор и журнал проверки источников. Не отчёт о готовности прогнозов.
Сборка сайта, тесты модели и деплой остаются на паузе.

## Как читать статусы

`PAGE_RECEIVED_DATA_NOT_VERIFIED`: получена страница; таблица, архив и выгрузка не подтверждены.
`POSSIBLE_CHALLENGE_PAGE`: ответ похож на защитную страницу; не считать данными.
`SEASONS_PARSED`: разобрана выборочная карьера; полнота остальных игроков неизвестна.
`TABLE_RECEIVED`: получен табличный ответ; это не подтверждает весь архив.
`EVENTS_RECEIVED`: получены события выбранного года; не все годы и не все box scores.
`JSON_RECEIVED_SCHEMA_NOT_ACCEPTED`: JSON есть, адаптер нормализации не принят.
`EMPTY_OR_UNSUPPORTED`: нет пригодных данных; это не доказательство отсутствия выступлений.
`REQUEST_OR_PARSE_FAILED`: источник или парсер не отработал; текст ошибки сохранён.

`coverageStatus=NOT_ESTABLISHED` применяется ко всем выборочным проверкам.
В каждой записи отдельно отражается способ доступа и его ограничения.
HTTP 200 не подтверждает право массовой выгрузки и не означает заполненную базу.

## Приоритеты и конкретные решения

| Блок | Основной кандидат / резерв | Глубина | Условие принятия адаптера |
|---|---|---|---|
| Sports.ru | Датированный аутентифицированный каталог / предыдущий подтверждённый снимок | Текущий каталог и последующие изменения | Проверка авторизации, всех страниц и всех ID; Sports-позиции не расширяются Yahoo |
| Правила | Sports.ru + подтверждённые комиссаром ограничения | Версии с датами действия | Зафиксировать каждый бонус, зачёт матчей и правила управления составом |
| NBA seasons | Официальная NBA как эталон; работающий канал ESPN | От дебюта каждого целевого игрока | Реестр ожидаемых сезонов и сверка игр/сумм, включая обмены |
| NBA games | Официальные протоколы / ESPN / имеющиеся parquet | Все доступные матчи, типы сезона отдельно | Сверка индивидуальных сумм с сезоном, командных — со счётом |
| Advanced | NBA Stats; расчетный proxy отдельно | Глубина каждого поля устанавливается отдельно | Согласовать способ доступа; проверить USG/TS/AST/REB/pace по выборке и единицы |
| Lineup/PBP | NBA Stats и play-by-play | Доступные сезоны и отрезки | Назначения пятёрок, замены, минуты, владения и нарушения реконструкции |
| Tracking | NBA Stats | По каждому показателю и сезону | Доказать наличие нужных таблиц и частоту обновления |
| NCAA | NCAA/университеты; ESPN как канал | Все команды, сезоны и доступные матчи | Не терять переходы между колледжами и не подменять отсутствие нулём |
| Summer League | NBA/организаторы; ESPN как резерв | Все турниры и годы участия | Проверить реальные коды турниров, календарь, архив, box scores и пагинацию |
| Preseason | NBA/ESPN с типом сезона | Все доступные годы | Подтвердить фильтр; не смешивать с regular/postseason |
| G League | Официальная статистика | Карьера игрока, турниры раздельно | Даты, этапы, two-way и перемещения согласованы |
| International | Организаторы конкретных лиг + FIBA для её турниров | Вся установленная клубная/сборная история | Сначала составить перечень лиг по игрокам; FIBA не покрывает все клубные лиги |
| Coaches | Официальные объявления и media guides | Все установленные периоды | События начала/конца, interim, источник и дата доступности |
| Injuries | NBA reports/команды; ESPN дополнительно | Все доступные выпуски и история участия | Статус, причина, предположение о возвращении разделены; DNP не автоматически травма |
| Calendar | NBA / ESPN | Сезон и исправления | Переносы, actual date, back-to-back, часовые пояса; история версий |
| Projections/ADP | ESPN snapshots | Только реально сохранённые даты | Нельзя восстановить старый прогноз сегодняшними значениями |
| Historical universe | NBA index, draft/roster histories; ESPN index | Активные, неактивные, не закрепившиеся | Проверить пагинацию и фильтры; нынешние ростеры не обучающая вселенная |

  Это временная контрольная точка, не постоянное хранилище онлайн-сервиса.

## Проверки, которые остаются обязательными

1. Реестр ID с происхождением, датой рождения, карьерными командами и конфликтами.
2. Для каждого игрока независимое ожидание сезонов; отсутствующий ответ не равен отсутствующему сезону.
3. Для каждой лиги перечень реально существовавших турниров/годов и соответствующих кодов поставщика.
4. Для каждого года полнота календаря/пагинации, завершённые события и доступные протоколы.
5. Массовая выгрузка, условия доступа и резервный источник — отдельное решение от наличия веб-страницы.
6. Для каждой метрики единицы, определение, исправления и доступность на дату прогноза.
7. Публичные источники не предоставляют полную медицинскую историю или закрытую тактику тренера.
   Эти ограничения нельзя устранить сбором дополнительных публичных страниц.
8. Исторические травмы, coaching tenures, PBP, международные лиги и постоянный backend
   пока не имеют принятого адаптера; они перечислены в машинном отчёте.

## Воспроизводимость

`scripts/audit_data_sources.py` выполняет ограниченные read-only запросы по
22 кандидатам, записывает время, URL, HTTP-статус, SHA-256 и краткое описание схемы.
`data/source-audit.json` — результат конкретного запуска, а не постоянный рейтинг источника.
`.github/workflows/source-audit.yml` запускает только этот аудит и сохраняет отчёт.
Он не запускает модель, тесты, симуляции, сборку или публикацию сайта.

`data/source-audit.json` — результат Actions; `data/source-audit-workspace.json` —
первый запуск из workspace. В первоначальном workspace-аудите эвристика защиты
искала captcha во всей странице и могла давать ложные срабатывания. Поэтому
`POSSIBLE_CHALLENGE_PAGE` в том файле не подтверждает блокировку. В Actions
эвристика ограничена заголовком страницы. Первоначальный лимит размера ответа
также прервал получение календаря: это локальный лимит аудитора, не отсутствие
данных у источника. Различия окружений сохранены, а не скрыты.

`data/source-policy.json` фиксирует правила происхождения, идентификации,
свежести, пропусков, конфликтов и условия приёмки источника.

## Восстановленные карьеры

`data/recovered-careers.json`: повторная обработка исходных ответов Hield
(10 сезонов), Bridges (8), Carter (8). Сохраняются все per-game компоненты
и игры по сезонам. Сезоны Hield 2023/24 — 84 игры, Bridges 2022/23 — 83.
Первоначальное время получения этих локальных ответов не сохранилось;
`fetchedAt=null`, время обработки и SHA-256 указаны отдельно. Это честно
обозначенный пробел происхождения, который нужно закрыть свежей загрузкой.
Данные пока не встроены в опубликованный каталог и независимо не сверены.

### Подтверждение исторического alias California Classic

Actions: https://github.com/RuslanMunasipov/Nba-draft-simulator/actions/runs/39095293686
`nba-summer-sacramento` за 2024 вернул 12 уникальных событий; один протокол
разобран (21 строка игроков). Таким образом подтверждены рабочие выборки:
2024 — sacramento; 2025/2026 — california. Таблица соответствий:
`data/competition-source-map.json`. Это подтверждение выборок, не полный сбор
всех протоколов и не утверждение о всех годах турнира.

Нормализованное название соревнования должно быть независимо от кода ESPN.
Иначе один код теряет новые сезоны, другой — старые. В исходной очереди
`collect_history.py` перечислены экспериментальные competition endpoints;
пока их сезонные stats endpoints не приняты как полный сбор Summer League.
Для летней лиги рабочий маршрут — scoreboard → event summary → игрок/матч.

Месячные range-запросы ESPN (`20261001-20261031`, `20261101-20261130`) тоже
вернули 400. Эти формы запроса не приняты. Рабочая выборка календаря остаётся
per-team schedule; ежедневные scoreboard используются существующим адаптером,
но полнота сезона ещё не установлена. Ошибку фильтра дат не маскируем как
«в сезоне нет матчей».

### Что изменяется в плане сбора

1. Сохранять канонический турнир отдельно от provider league code и года.
2. Летнюю лигу собирать по проверенному календарю событий, не ожидать от
   athlete/stats полного career-архива SL.
3. Для NCAA приоритет сверки — официальные университетские сезонные таблицы,
   пока централизованный источник недоступен из Actions.
4. Календарь NBA собирать из командных расписаний с последующим объединением,
   дублями по event ID и явными пока не назначенными играми; не выдавать 80 за 82.
5. NBA advanced не объявлять постоянно доступным: ограничения окружения остаются.
6. Пропуски USG/lineup/tracking не заполнять значениями ESPN, которых там нет.

## Переход от выборок к протоколам Summer League

За 2024–2026 собраны все 276 протоколов из девяти проверенных календарей ESPN.
Нормализованы 5881 строка по 989 ESPN ID. После повторения двух временных
ошибок загрузки потерь протоколов нет. 250 событий без предупреждений
реализованных проверок, 26 с явными предупреждениями. Детали и ограничения:
`docs/SUMMER_COLLECTION.md`, `data/summer-games-coverage.json`.
Независимая календарная полнота по-прежнему не установлена.
