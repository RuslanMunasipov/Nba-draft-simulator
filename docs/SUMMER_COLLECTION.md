# Сбор Summer League 2024–2026

Скрипт: `scripts/collect_summer_games.py`.
Запуск: `python scripts/collect_summer_games.py`.
Это сбор и сверка наблюдений; модель, unit/integration tests, приложение и деплой
не запускаются.

## Охват

Девять календарей из `data/competition-source-map.json`:
Las Vegas, Salt Lake City, California Classic за 2024, 2025 и 2026.
California Classic использует проверенный код ESPN по году.
Количество событий сверяется с предыдущей выборкой. Изменение счётчика отражается
в отчёте и не скрывается.

## Содержимое результата

- `calendars.json`: полученные календари с метаданными источника.
- `games.ndjson`: по одной записи на событие, включая ошибки и предупреждения.
- `raw/`: исходные JSON-ответы, gzip по SHA-256.
- `requests/`: URL, время загрузки, неизвестное время публикации как null,
  HTTP-статус, хеш, путь к исходному ответу.
- `coverage.json`: итог по турнирам и годам, полученные события, строки игроков,
  число уникальных ESPN ID и список проблем.

Для каждого игрока сохраняются все статистические компоненты имеющегося
box-score parser: минуты, очки, подборы, передачи, перехваты, блоки, потери,
фолы, FGM/FGA, FTM/FTA. Исходный протокол сохраняет и остальные поля источника.
Флаг стартера может отсутствовать; это не автоматически выход со скамейки.

Контекст: канонический турнир, код источника, год, event ID, дата,
команда, домашняя/гостевая сторона, счёт и победитель, если поставщик их указал.
Летние матчи не получают фиктивных NBA-ФО, USG или медицинских диагнозов.

## Сверка без потери строк

1. Календарь не пуст, не достиг лимита 1000, не содержит повторных ID,
   даты принадлежат запрошенному году.
2. Event ID в протоколе совпадает с запрошенным, если поставщик его вернул.
3. Игрок привязан к одной из двух команд протокола.
4. Повторный игрок в нормализованных строках — ошибка, не удвоение статистики.
5. Строки участия/DNP сохраняются отдельно. Каждая non-DNP строка, которую
   парсер не принял, перечислена с исходными полями; она не исчезает молча.
6. Сумма очков нормализованных игроков сверяется со счётом каждой команды.
7. Незавершённые события и ошибки загрузки имеют отдельные статусы.

Это не полная верификация всех полей: командные подборы/потери, секунды,
замены, игровые отрезки и другие компоненты нуждаются в отдельной сверке.
Нулевая минута не автоматически DNP, отсутствие причины не диагноз.

## Граница полноты

Все полученные протоколы из списка ESPN не доказывают полноту самого списка.
Независимая сверка календаря NBA/организатора отмечается отдельно и пока false.
Этот этап покрывает только указанные три года, а не всю историю Summer League.
Совпадения ESPN ID позволяют строить связи, но обучение по нынешнему каталогу
по-прежнему не заменяет историческую вселенную игроков.

Raw-ответы и нормализованные записи сохраняются artifact в Actions на 90 дней.
Это контрольная точка, не уже развёрнутая постоянная онлайн-база.
Обновление приложения или прогнозов не является частью этого workflow.

## Уточнения по исходным минутам и правилам

У некоторых игроков источник записывает MIN=0 при ненулевой статистике.
Такие строки теперь сохраняются: `ZERO_REPORTED`, `eligibleForRateFeatures=false`.
Нулевая запись минут не равна пропуску; её нельзя использовать как делитель
для per-minute показателей. MIN=`--` остаётся неизвестным и сохраняется в
строке участия с исходной статистикой и предупреждением.

Правила 2026: https://www.nba.com/news/nba-summer-league-free-throw-connected-basketball
и https://www.nba.com/news/2026-summer-league-format .
Один штрафной может приносить 1/2/3 очка; в конце четвёртой четверти и overtime
применяется стандартный режим. Поэтому обычное равенство PTS=2*FGM+3PM+FTM
не является валидным контролем для всех этих матчей. Нужна версия правил,
а для переноса в NBA — разбор стоимости штрафных по событиям. Значения
очков, попаданий и попыток сохраняются как наблюдения источника.
Сведения о правилах: `data/summer-rule-context.json`.

Совпадение имени и всей статистики у разных ESPN ID в одной команде отмечается
как `POSSIBLE_DUPLICATE_IDENTITIES`. Автоматического объединения ID нет.
